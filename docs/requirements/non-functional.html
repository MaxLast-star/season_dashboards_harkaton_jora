Нефункциональные требования (NFR)

Каждое NFR имеет ID, категорию, приоритет (MUST / SHOULD / COULD), само требование и обоснование.

Производительность​

:::note NFR-PERF-001 · MUST HAVE Время загрузки дашборда (первый рендер) не более 2 секунд при скорости соединения 10 Мбит/с.

Шеф-повар работает в напряжённом ритме кухни. Медленный интерфейс ведёт к отказу от инструмента. Порог 2 сек — стандарт для B2B-веб по исследованиям Google (более 53% пользователей уходят при загрузке свыше 3 сек). :::

:::note NFR-PERF-002 · MUST HAVE Генерация AI-объяснения не более 3 секунд на один продукт.

Основная ценность продукта — быстрые объяснения. Задержка свыше 5 сек воспринимается как «зависание» и снижает доверие к AI-функционалу. :::

:::note NFR-PERF-003 · SHOULD HAVE Система выдерживает от 500 одновременных пользователей без деградации времени ответа более чем на 50%.

При MAU 5000 шефов и рабочем окне 8–14 часов ожидаемый пик — ~300–500 одновременных сессий. :::

Надёжность​

:::note NFR-REL-001 · MUST HAVE Доступность от 99% в рабочие часы (08:00–22:00 МСК) = не более 7.2 часа простоя в месяц.

Рестораны работают с раннего утра до поздней ночи. Недоступность в часы пик планирования меню критична. :::

:::note NFR-REL-002 · MUST HAVE При недоступности API svoe-rodnoe.ru — автоматическое переключение на кэш (TTL 24ч) с уведомлением о давности данных.

Зависимость от внешнего API — ключевой риск R5. Кэш гарантирует работоспособность при сбоях партнёрского сервиса. :::

:::note NFR-REL-003 · SHOULD HAVE RTO не более 30 минут, RPO не более 1 часа.

Восстановление в течение 30 минут минимизирует потери пользовательского доверия. Потеря данных за последний час допустима — контент каталога статичен. :::

Безопасность​

:::note NFR-SEC-001 · MUST HAVE HTTPS (TLS 1.2+). Пароли — bcrypt с cost от 12. API-ключи — в environment variables, не в коде.

Пользователи передают данные меню ресторана — конфиденциальную бизнес-информацию. :::

:::note NFR-SEC-002 · MUST HAVE Авторизация через систему svoe-shef.ru (SSO / OAuth 2.0). Сессия истекает через 8 часов бездействия.

Единая авторизация исключает дублирование аккаунтов и соответствует стандартам платформы РСХБ. :::

:::note NFR-SEC-003 · SHOULD HAVE Rate limiting на AI-запросы: не более 60 запросов в минуту на пользователя. При превышении — HTTP 429.

Защита от злоупотреблений LLM API, тарифицируемого по токенам. :::

Удобство использования (Usability)​

:::note NFR-UX-001 · MUST HAVE Новый пользователь достигает первого результата (видит подборку продуктов) за 5 шагов и 3 минуты без инструкции.

Критерий оценки хакатона — «минимизация действий». Шеф-повара — практики, не технари. :::

:::note NFR-UX-002 · SHOULD HAVE Адаптация для экранов от 1024px. Мобильная версия — v2.0.

Шефы преимущественно работают с планшетом или ноутбуком. :::

:::note NFR-UX-003 · COULD HAVE Поддержка тёмной темы (переключатель в настройках).

Кухни часто имеют специфическое освещение. Тёмная тема снижает нагрузку на глаза. :::

Поддерживаемость (Maintainability)​

:::note NFR-MAINT-001 · SHOULD HAVE Тестовое покрытие бизнес-логики от 70% unit-тестами.

Алгоритм подбора продуктов — ключевая ценность системы. Без тестов любое изменение рискует сломать основную функцию. :::

:::note NFR-MAINT-002 · SHOULD HAVE База сезонности продуктов — в конфигурационном файле (JSON/YAML), не закодирована в бизнес-логике. Обновление без деплоя.

Сезонные окна меняются год от года и требуют регулярной корректировки. :::

Совместимость​

:::note NFR-COMPAT-001 · MUST HAVE Браузеры: Chrome от 90, Firefox от 88, Safari от 14, Edge от 90. Без дополнительных плагинов.

Ограничение браузерами последних 2 лет охватывает более 95% реальных пользователей. :::

:::note NFR-COMPAT-002 · MUST HAVE API интеграции с svoe-rodnoe.ru — REST + JSON. Обратная совместимость при изменении схемы — минимум 3 месяца.

Изменения на стороне svoe-rodnoe.ru не должны моментально ломать работу дашборда. :::
