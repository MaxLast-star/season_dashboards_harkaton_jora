# Бизнес-требования

## 1. Описание проблемы

### 1.1 Перечень проблем

| № | Проблема | Критичность |
|---|---|---|
| P1 | **Отсутствие визуального инструмента сезонности.** Шеф-повар не имеет единого дашборда: что сейчас в сезоне, что скоро появится, что заканчивается. Решение принимается «из головы» или через ручной поиск. | 🔴 Критическая |
| P2 | **Ручной поиск фермеров и продуктов.** Поиск через личные контакты, Telegram-чаты и Авито — непрозрачен, занимает часы. | 🔴 Критическая |
| P3 | **Невозможность заблаговременного планирования закупок.** Без понимания «окна сезонности» ресторан не может заранее согласовать объём с фермером. | 🟠 Высокая |
| P4 | **Несоответствие меню типу кухни и сезону.** При подборе продуктов нет автоматической фильтрации по концепции кухни. | 🟠 Высокая |
| P5 | **Отсутствие объяснений совместимости.** Даже если продукт найден, шеф не получает обоснования применения. | 🟡 Средняя |
| P6 | **Изолированность svoe-shef.ru и svoe-rodnoe.ru.** Каталог фермерских продуктов существует отдельно от инструментов планирования. | 🟡 Средняя |

### 1.2 Текущие альтернативы и их недостатки

| Альтернатива | Недостатки |
|---|---|
| Excel / Google Sheets | Не обновляется автоматически, нет интеграции с каталогом фермеров |
| Поиск через Авито / Telegram | Не структурирован, нет фильтра по типу кухни |
| Личные контакты шефа | Ограниченный охват, зависимость от «сарафанного радио» |
| Общие агрегаторы (СберМаркет и пр.) | Нет фокуса на сезонность и фермерское происхождение |

### 1.3 Главная боль

:::info Ключевая проблема
Шеф-повар тратит значительное время на ручной поиск сезонных продуктов, не видит целостной картины сезонности и не может быстро найти подходящего фермера под свою концепцию кухни — что замедляет обновление меню и снижает конкурентоспособность ресторана.
:::

## 2. Целевая аудитория

| Роль | Описание | Потребности |
|---|---|---|
| **Шеф-повар** (первичный) | Создаёт и обновляет меню. Работает в ресторане авторской кухни. | Быстро видеть актуальные продукты; получать релевантные предложения под кухню |
| **Менеджер / закупщик** (вторичный) | Отвечает за закупки и бюджет. | Прозрачность планирования, предсказуемость наличия продуктов |
| **Владелец ресторана** (наблюдатель) | Заинтересован в снижении издержек и росте среднего чека. | Сводные отчёты, метрики бизнес-результата |
| **Фермер** (поставщик данных) | Предоставляет продукцию через svoe-rodnoe.ru. | Получать запросы от релевантных ресторанов |

## 3. Бизнес-цели и KPI

### SMART-цели

| ID | Цель | Метрика | Срок |
|---|---|---|---|
| BG-01 | Сократить время поиска с ~2 ч до ≤15 мин | Среднее время сессии при поиске | MVP + 3 мес. |
| BG-02 | Покрытие ≥80% запросов релевантными предложениями | % запросов с ≥3 продуктами | MVP + 3 мес. |
| BG-03 | MAU ≥ 5 000 шефов | MAU в панели аналитики | MVP + 6 мес. |
| BG-04 | Конверсия «просмотр → фермер» ≥ 25% | CTR кнопки «Найти фермера» | MVP + 3 мес. |
| BG-05 | Рост B2B-транзакций на svoe-rodnoe.ru на 30% | Заказы с тегом «ресторан» | MVP + 6 мес. |

### KPI с методом измерения

| KPI | Метод измерения |
|---|---|
| Время поиска продукта | Аналитика сессий (вход на дашборд → клик «перейти к фермеру») |
| % релевантных результатов | A/B тест + NPS-опрос шефов |
| MAU | Уникальные авторизованные пользователи за 30 дней |
| CTR фермерской карточки | Клики / показы кнопки |
| Рост B2B-транзакций | Данные из CRM svoe-rodnoe.ru |

## 4. Риски

| ID | Риск | Вероятность | Влияние | Стратегия |
|---|---|---|---|---|
| R1 | Неполный каталог svoe-rodnoe.ru (мало фермеров, неточная сезонность) | Средняя | Высокое | Предварительная валидация; резервная ручная база сезонности |
| R2 | Шефы не загружают меню (низкий онбординг) | Средняя | Высокое | Ручной ввод типа кухни как fallback; упрощённый UX |
| R3 | Низкое качество AI-объяснений | Высокая | Среднее | Human-in-the-loop проверка шаблонов; ограничения для MVP |
| R4 | Юридические ограничения на использование данных svoe-rodnoe.ru | Низкая | Критическое | Согласовать API-доступ с РСХБ до старта разработки |
| R5 | Перегрузка API svoe-rodnoe.ru при масштабировании | Низкая | Высокое | Кэширование данных каталога; TTL 24 часа |
| R6 | Пользователи не доверяют AI-рекомендациям | Средняя | Среднее | Показывать источник данных; добавить рейтинг релевантности |
