# Функциональные требования (FR)

> Все требования описаны для **MVP v1.0**. Критерии приёмки нумеруются сквозно.

---

## FR-MENU: Управление меню ресторана

| ID | Требование |
|---|---|
| FR-MENU-01 | Система должна позволять шефу загрузить меню в формате PDF или вставить текст вручную |
| FR-MENU-02 | Система должна парсить загруженное меню и извлекать названия блюд |
| FR-MENU-03 | Система должна определять тип кухни из справочника на основе анализа блюд или ручного выбора |
| FR-MENU-04 | Шеф может вручную скорректировать тип кухни после автоопределения |

### Use Case: UC-MENU-001 — Загрузка меню ресторана

| Поле | Значение |
|---|---|
| **ID** | UC-MENU-001 |
| **Акторы** | Шеф-повар, Система (парсер, AI-классификатор) |
| **Предусловия** | Шеф авторизован; меню подготовлено в формате PDF или текстом |

**Основной поток:**
1. Шеф открывает раздел «Дашборд сезонности»
2. Система отображает экран загрузки меню
3. Шеф загружает PDF или вставляет текст меню
4. Система парсит меню: извлекает названия блюд
5. AI-классификатор определяет тип кухни и выводит его шефу
6. Шеф подтверждает тип кухни или корректирует его вручную
7. Система сохраняет меню и тип кухни в профиле ресторана
8. Система переходит к экрану дашборда сезонности

**Альтернативные потоки:**
- **A1.** Шеф выбирает тип кухни вручную — показывается список из справочника — переход к п.7

**Исключительные потоки:**
- **E1.** PDF не поддаётся парсингу (скан без OCR) — «Не удалось распознать текст. Введите меню вручную»
- **E2.** Уверенность классификатора ниже 70% — показываются топ-3 кандидата с вероятностями

**Критерии приёмки:**
1. Система принимает PDF весом до 10 МБ
2. Парсинг завершается за 10 секунд или быстрее
3. Точность классификации кухни от 75% на тестовой выборке из 20 меню
4. При ошибке парсинга система отображает понятное сообщение на русском языке
5. Тип кухни всегда можно изменить вручную

## FR-SEASON: Визуализация сезонности

| ID | Требование |
|---|---|
| FR-SEASON-01 | Система должна отображать тайм-лайн сезонности (текущий + 2 следующих месяца) |
| FR-SEASON-02 | Каждый продукт должен иметь цветовой статус: 🟢 в сезоне / 🟡 скоро / 🔴 заканчивается / ⚪ вне сезона |
| FR-SEASON-03 | Система должна автоматически определять текущий сезон по дате системы |
| FR-SEASON-04 | Тайм-лайн группируется по категориям продуктов (овощи, ягоды, грибы, рыба и пр.) |

### Use Case: UC-SEASON-001 — Просмотр дашборда сезонности

**Основной поток:**
1. Шеф открывает дашборд сезонности
2. Система определяет текущий сезон по дате
3. Система отображает тайм-лайн: сетка «продукт × месяц» на 3 месяца вперёд
4. Каждая ячейка окрашена в соответствии со статусом сезонности
5. Шеф применяет фильтры: по кухне / категории / статусу / типу продукта
6. При наведении на продукт — карточка с кратким описанием

**Исключительные потоки:**
- **E1.** Для кухни шефа нет данных — показываются все продукты + предупреждение

**Критерии приёмки:**
1. Тайм-лайн отображается за 2 секунды или быстрее после загрузки страницы
2. На экране одновременно видны минимум 3 месяца
3. Фильтры работают без перезагрузки страницы
4. При отсутствии данных отображается корректный fallback

## FR-RECO: Подбор продуктов и рекомендации

| ID | Требование |
|---|---|
| FR-RECO-01 | Система подбирает продукты по критериям: текущий сезон + тип кухни ресторана |
| FR-RECO-02 | Для каждого продукта: название, фото, фермер, регион, цена, статус сезонности |
| FR-RECO-03 | Система выделяет «редкие» и «премиальные» продукты специальными бейджами |
| FR-RECO-04 | Для каждого продукта генерируется AI-объяснение совместимости (1–3 предложения) |
| FR-RECO-05 | Система показывает, какие позиции из меню можно обновить данным продуктом |

### Use Case: UC-RECO-001 — Подбор сезонных продуктов

**Основной поток:**
1. Система запрашивает продукты из svoe-rodnoe.ru (фильтр: текущий сезон)
2. Фильтрует по совместимости с типом кухни
3. Ранжирует: сначала «в сезоне», затем «скоро»
4. Генерирует AI-объяснение для каждого продукта
5. Определяет блюда из меню, которые можно обновить
6. Шеф нажимает «Перейти к фермеру» — страница svoe-rodnoe.ru в новой вкладке

**Исключительные потоки:**
- **E1.** API svoe-rodnoe.ru недоступен — кэш (TTL 24ч) + уведомление о давности данных
- **E2.** Продуктов нет — расширение поиска до смежных кухонь + уведомление шефу

**Критерии приёмки:**
1. Подборка содержит от 5 продуктов для любого из 10 основных типов кухонь
2. AI-объяснение генерируется для каждого продукта (1–3 предложения)
3. Кнопка «Перейти к фермеру» ведёт на корректную карточку svoe-rodnoe.ru
4. При недоступности API показываются кэшированные данные не старше 24 часов

## FR-CATALOG: Интеграция с каталогом svoe-rodnoe.ru

| ID | Требование |
|---|---|
| FR-CATALOG-01 | Система получает данные из каталога svoe-rodnoe.ru через API |
| FR-CATALOG-02 | Данные каталога кэшируются с TTL 24 часа |
| FR-CATALOG-03 | Поддерживается фильтрация по: категории, региону фермера, сезонному статусу |
| FR-CATALOG-04 | При переходе к фермеру — карточка svoe-rodnoe.ru открывается в новой вкладке |
