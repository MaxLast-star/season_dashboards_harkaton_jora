# Технологический стек и бизнес-ценность

## 1. Готовые решения vs. собственная разработка

### Что берём готовым (не пишем с нуля)

| Компонент | Выбранное решение | Обоснование |
|---|---|---|
| **Авторизация** | SSO svoe-shef.ru / OAuth 2.0 | Платформа уже имеет авторизацию; дублирование создаёт риски |
| **LLM для объяснений** | GigaChat API / YandexGPT | Российские провайдеры: данные в РФ, нет рисков санкций |
| **Парсинг PDF** | pdfplumber (Python) / pdf-parse (Node.js) | Зрелые open-source библиотеки |
| **База данных** | PostgreSQL (Supabase / Neon) | Managed-сервис снимает DevOps |
| **Кэш** | Redis (Upstash) | Бесплатный тир достаточен для прототипа |
| **Аналитика** | PostHog | Воронки, retention, события — без собственного BI |
| **Деплой прототипа** | Railway / Render | Деплой за 5 минут |

### Что разрабатываем сами (уникальная ценность)

| Модуль | Почему нельзя заменить |
|---|---|
| **Матрица совместимости продукт × кухня** | Экспертная база для российского рынка; готовых аналогов нет |
| **Алгоритм ранжирования и подбора** | Бизнес-логика: сезон + кухня + редкость |
| **Интеграция с svoe-rodnoe.ru** | Эксклюзивный источник данных о 10 000+ российских фермеров |
| **Промпты и контекстуализация AI** | Шаблоны под ресторанный домен и конкретное меню шефа |
| **Визуальный тайм-лайн** | UX под специфику работы шефа (мыслит сезонами и категориями блюд) |

## 2. Бизнес-ценность в числах

### Ценность для шеф-повара

| Проблема до | Решение | Результат |
|---|---|---|
| Поиск занимает 1–3 часа (Telegram, Авито, звонки) | Дашборд подбирает за секунды | Сокращение с ~2 ч до 15 мин (BG-01) |
| Нет понимания «окна сезонности» | Тайм-лайн на 3 месяца вперёд | Планирование меню за 8 недель, не постфактум |
| Продукты без учёта кухни — много нерелевантного | Фильтр + AI-объяснение | Из 100 продуктов шеф видит только релевантные |
| Нет обоснования «зачем этот продукт мне» | 2–3 предложения с AI-обоснованием | Конверсия ≥ 25% (BG-04) |

### Ценность для ресторана

| Метрика | До | Цель | Как считаем |
|---|---|---|---|
| Время обновления сезонного меню | 3–7 дней | 1 день | Опрос шефов через 3 мес. |
| Доля сезонных позиций в меню | 10–20% | 30–40% | Анализ загружаемых меню |
| Маржинальность сезонных блюд | Базовая | +5–10% | Опрос рестораторов через 6 мес. |
| Среднее количество поставщиков | 2–3 | 5–7 | Данные из svoe-rodnoe.ru |

### Ценность для платформы РСХБ

| Метрика | Цель | Горизонт |
|---|---|---|
| MAU шефов на svoe-shef.ru | +5 000 пользователей модуля | 6 мес. |
| CTR «К фермеру» | 25% просмотров → переход | 3 мес. |
| Рост B2B-транзакций svoe-rodnoe.ru | +30% заказов с тегом «ресторан» | 6 мес. |
| Retention шефов | +40% удержание vs. без модуля | 3 мес. |
| NPS шефов | ≥ 50 | 3 мес. |

## 3. Value Flywheel

```
Шеф находит продукт через дашборд
          ↓
Переходит на svoe-rodnoe.ru → покупает у фермера
          ↓
Фермер получает выручку → обновляет каталог → добавляет сезонные продукты
          ↓
Каталог богаче → дашборд даёт лучшие рекомендации
          ↓
Больше шефов → больше трафика на svoe-rodnoe.ru
          ↓
РСХБ видит рост транзакций → кредитует фермеров под сезонные закупки
          ↓
          (цикл повторяется)
```

## 4. Технологический стек

| Слой | Технология | Обоснование |
|---|---|---|
| **Frontend** | React + TypeScript | Компонентный подход для переиспользования карточек и фильтров |
| **Backend** | Node.js (Express) или Python (FastAPI) | Оба поддерживают async для AI-запросов |
| **База данных** | PostgreSQL | Транзакционность, JSONB, зрелость |
| **Кэш** | Redis | TTL 24ч для каталога, TTL 1ч для AI-ответов |
| **LLM** | GigaChat API / YandexGPT | Российские провайдеры, данные в РФ |
| **Парсинг PDF** | pdfplumber (Python) | Надёжный open-source |
| **Аналитика** | PostHog | Воронки, retention без собственного BI |
| **Деплой** | Railway / Render | Быстро, без DevOps для прототипа |
| **Мониторинг ошибок** | Sentry | Бесплатный тир, интеграция за 5 минут |
