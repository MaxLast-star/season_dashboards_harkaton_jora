## 3. Детальное описание участия каждого стейкхолдера

### SH-01 Шеф-повар
- **R (исполнитель):** Загрузка меню, выбор/корректировка типа кухни, работа с дашбордом, переход к фермерам
- **C (консультант):** Определение бизнес-требований, UX-тестирование прототипа
- Основная ценность: валидация гипотез через реальное использование продукта

### SH-02 Менеджер / закупщик
- **I (информируемый):** Получает результаты подборки от шефа для оформления заказов
- **C (консультант):** Тестирование сценариев планирования закупок
- Ограниченное участие в MVP; станет активнее в v2.0 (планировщик закупок)

### SH-03 Владелец ресторана
- **A (ответственный):** Мониторинг KPI после запуска (ROI от сезонных продуктов)
- **I (информируемый):** Получает аналитику и отчёты (v2.0+)
- В MVP — наблюдатель; не взаимодействует с системой напрямую

### SH-04 Product Manager svoe-shef.ru
- **A (ответственный):** Все ключевые продуктовые решения: приоритет функций, go/no-go
- **R (исполнитель):** Определение требований совместно с командой разработки
- Главный stakeholder со стороны платформы; его согласование необходимо на каждом этапе

### SH-05 Команда svoe-rodnoe.ru
- **A (ответственный):** Актуализация данных каталога; предоставление API
- **C (консультант):** Структура данных, правила доступа к каталогу, ограничения API
- Критичный технический партнёр: без данных о продуктах сервис не работает

### SH-06 Фермер
- **R (исполнитель):** Наполнение своей карточки на svoe-rodnoe.ru (описание продуктов, сезоны, фото)
- **A (ответственный):** Актуализация данных о наличии и сезонности своей продукции
- Косвенный участник: данные фермера используются системой, но он не взаимодействует с дашбордом шефа напрямую

### SH-07 РСХБ
- **A (ответственный):** Стратегические решения: финансирование, интеграция экосистемы
- **I (информируемый):** Ход разработки, результаты хакатона, KPI платформ
- Финальный арбитр приоритетов при конфликте интересов платформ

### SH-08 Команда разработки (хакатон)
- **R (исполнитель):** Проектирование, разработка, тестирование всех компонентов MVP
- Несёт техническую ответственность за реализацию в рамках хакатона

## 4. Вопросы для стейкхолдеров

### SH-01 Шеф-повар

1. **Как вы сейчас определяете, какие продукты сезонные и доступны у фермеров?**
   _Цель: понять текущий рабочий процесс и выявить «болевые точки», которые система должна устранить_

2. **Сколько времени в среднем вы тратите на обновление меню под сезон?**
   _Цель: установить baseline для KPI BG-01 (сокращение времени поиска)_

3. **Какой формат меню вы используете? PDF, Word, или что-то другое?**
   _Цель: уточнить технические требования к парсеру меню (FR-MENU-01)_

4. **Что для вас важнее при выборе продукта: сезонность, редкость, цена или регион фермера?**
   _Цель: определить приоритеты ранжирования в алгоритме подбора (FR-RECO-01)_

5. **Что вы понимаете под «редким» или «премиальным» ингредиентом?**
   _Цель: формализовать критерии для бейджей «редкий» и «премиальный» (FR-RECO-03)_

6. **Готовы ли вы к тому, что объяснения будут сгенерированы AI? Что для вас важно в таком тексте?**
   _Цель: оценить доверие к AI-контенту и выявить требования к качеству генерации (риск R6)_

### SH-04 Product Manager svoe-shef.ru

1. **Есть ли у svoe-shef.ru уже API для работы с профилями шефов и ресторанов? Какие данные доступны?**
   _Цель: оценить возможность интеграции SSO и получения данных профиля (FR-AUTH-01)_

2. **Какой технический стек используется на платформе svoe-shef.ru?**
   _Цель: принять решение о совместимости и способе встраивания дашборда_

3. **Какие метрики платформы считаются приоритетными для оценки успеха нового модуля?**
   _Цель: согласовать KPI (BG-03, BG-04) с реальными целями платформы_

4. **Есть ли ограничения на использование AI (LLM) в продуктах РСХБ? Какие AI-провайдеры предпочтительны?**
   _Цель: принять решение об AI-провайдере (OpenAI / YandexGPT / GigaChat) с учётом требований безопасности_

5. **Каков план интеграции этого модуля в существующий личный кабинет? Отдельный раздел или встройка?**
   _Цель: определить архитектуру встраивания (iframe / микрофронтенд / нативная интеграция)_

### SH-05 Команда svoe-rodnoe.ru

1. **Есть ли публичный или закрытый API для доступа к каталогу продуктов? Какой формат данных?**
   _Цель: определить техническую возможность интеграции без веб-скрапинга (FR-CATALOG-01)_

2. **Есть ли в каталоге поле «сезонность» для каждого продукта? Как оно структурировано?**
   _Цель: понять, насколько данные готовы к использованию в дашборде (критический риск R1)_

3. **Каковы ограничения по количеству запросов к API? Возможно ли получить повышенный лимит для платформы svoe-shef.ru?**
   _Цель: оценить масштабируемость интеграции и необходимость кэширования (NFR-REL-002)_

4. **Как фермеры управляют данными о сезонности? Это ручное заполнение или автоматизировано?**
   _Цель: оценить актуальность данных и частоту обновления (риск R1)_

5. **Есть ли категоризация продуктов по типу кухни или это только по типу продукта?**
   _Цель: понять, нужна ли матрица совместимости «продукт × кухня» на нашей стороне или она уже реализована_

### SH-06 Фермер

1. **Как вы сейчас описываете сезонность своей продукции на платформе?**
   _Цель: понять качество данных о сезонности, которые попадут в дашборд шефа_

2. **Хотели бы вы получать уведомления о том, что ресторан заинтересовался вашей продукцией?**

3. **Насколько точно вы можете прогнозировать наличие продукта на 2–4 недели вперёд?**
   _Цель: оценить возможность функции «скоро появится» в дашборде_

4. **Что для вас значит «премиальный» продукт? Это цена, редкость, способ выращивания?**
   _Цель: уточнить критерии для бейджа «премиальный» (FR-RECO-03)_
