# 01. Функциональные требования (FR)

> Все требования описаны для MVP (v1.0). Критерии приёмки нумеруются сквозно.

---

## FR-MENU: Управление меню ресторана

**FR-MENU-01.** Система должна позволять шефу загрузить меню ресторана в формате PDF или вставить текст вручную.

**FR-MENU-02.** Система должна парсить загруженное меню и извлекать названия блюд.

**FR-MENU-03.** Система должна определять тип кухни из справочника (русская, итальянская, авторская и пр.) на основе анализа блюд или ручного выбора шефа.

**FR-MENU-04.** Шеф может вручную скорректировать тип кухни после автоопределения.

---

### Use Case: UC-MENU-001 — Загрузка меню ресторана

```
ID: UC-MENU-001
Наименование: Загрузка и обработка меню ресторана
Акторы: Шеф-повар, Система (парсер меню, AI-классификатор кухни)
Предусловия:
  - Шеф авторизован в личном кабинете svoe-shef.ru
  - Меню подготовлено в формате PDF или текстом

Основной поток:
  1. Шеф открывает раздел «Дашборд сезонности»
  2. Система отображает экран загрузки меню
  3. Шеф загружает PDF или вставляет текст меню
  4. Система парсит меню: извлекает названия блюд
  5. AI-классификатор определяет тип кухни и выводит его шефу
  6. Шеф подтверждает тип кухни или корректирует его вручную
  7. Система сохраняет меню и тип кухни в профиле ресторана
  8. Система автоматически переходит к экрану дашборда сезонности

Постусловия:
  - Меню и тип кухни сохранены
  - Дашборд сформирован с учётом текущего сезона и кухни

Альтернативные потоки:
  A1. Шеф выбирает тип кухни вручную (без загрузки меню):
    A1.1. Шеф нажимает «Выбрать кухню вручную»
    A1.2. Система показывает список типов кухонь из справочника
    A1.3. Шеф выбирает тип кухни
    A1.4. Переход к п.7 основного потока

Исключительные потоки:
  E1. PDF не поддаётся парсингу (скан без OCR):
    E1.1. Система уведомляет: «Не удалось распознать текст. Введите меню вручную»
    E1.2. Шеф вводит меню текстом
  E2. Тип кухни не определён с уверенностью >70%:
    E2.1. Система показывает топ-3 кандидата с вероятностями
    E2.2. Шеф выбирает из предложенных или вводит вручную

Критерии приёмки:
  1. Система принимает PDF весом до 10 МБ
  2. Парсинг завершается за ≤10 секунд
  3. Точность классификации кухни ≥75% на тестовой выборке из 20 меню
  4. При ошибке парсинга система отображает понятное сообщение на русском языке
  5. Тип кухни всегда можно изменить вручную
```

## FR-SEASON: Визуализация сезонности

**FR-SEASON-01.** Система должна отображать календарь сезонности по месяцам (текущий + 2 следующих месяца) в виде визуального тайм-лайна.

**FR-SEASON-02.** Каждый продукт в тайм-лайне должен иметь цветовой статус: 🟢 в сезоне / 🟡 скоро начнётся / 🔴 заканчивается.

**FR-SEASON-03.** Система должна автоматически определять текущий сезон по дате системы.

**FR-SEASON-04.** Тайм-лайн должен быть сгруппирован по категориям продуктов (овощи, ягоды, грибы, мясо, рыба, молочные и пр.).

---

### Use Case: UC-SEASON-001 — Просмотр дашборда сезонности

```
ID: UC-SEASON-001
Наименование: Просмотр визуального дашборда сезонности
Акторы: Шеф-повар, Система
Предусловия:
  - Меню загружено и тип кухни определён (UC-MENU-001 выполнен)
  - Текущая дата известна системе

Основной поток:
  1. Шеф открывает дашборд сезонности
  2. Система определяет текущий сезон (весна/лето/осень/зима) по дате
  3. Система отображает тайм-лайн: сетка «продукт × месяц» на 3 месяца вперёд
  4. Каждая ячейка окрашена в соответствии со статусом сезонности
  5. Шеф может применить фильтры: по категории, по статусу, по типу («редкий», «премиальный»)
  6. При наведении на продукт — всплывающая карточка с кратким описанием

Постусловия:
  - Шеф видит актуальную карту сезонности под свою кухню

Альтернативные потоки:
  A1. Шеф хочет посмотреть другой месяц:
    A1.1. Шеф нажимает стрелку «вперёд» / «назад»
    A1.2. Тайм-лайн сдвигается на указанный месяц

Исключительные потоки:
  E1. Для кухни шефа нет данных в каталоге:
    E1.1. Система показывает общий список сезонных продуктов без фильтрации по кухне
    E1.2. Выводится предупреждение: «Специфических продуктов для выбранной кухни не найдено. Показаны общие сезонные продукты»

Критерии приёмки:
  1. Тайм-лайн отображается за ≤2 секунды после загрузки страницы
  2. На экране одновременно видны минимум 3 месяца
  3. Цветовое кодирование статусов применено корректно для всех продуктов
  4. Фильтры работают без перезагрузки страницы
  5. При отсутствии данных отображается корректное fallback-сообщение
```

## FR-RECO: Подбор продуктов и рекомендации

**FR-RECO-01.** Система должна подбирать из каталога svoe-rodnoe.ru продукты, соответствующие: текущему сезону + типу кухни ресторана.

**FR-RECO-02.** Для каждого рекомендованного продукта система должна показывать: название, фото, фермер, регион, цена (если доступна), статус сезонности.

**FR-RECO-03.** Система должна выделять «редкие» и «премиальные» продукты специальными бейджами.

**FR-RECO-04.** Для каждого продукта система должна генерировать краткое объяснение (1–3 предложения): почему он подходит под данную кухню и сезон.

**FR-RECO-05.** Система должна показывать, какие позиции из меню ресторана можно обновить данным продуктом.

---

### Use Case: UC-RECO-001 — Подбор сезонных продуктов

```
ID: UC-RECO-001
Наименование: Автоматический подбор сезонных продуктов под кухню ресторана
Акторы: Шеф-повар, Система, Каталог svoe-rodnoe.ru
Предусловия:
  - UC-MENU-001 выполнен (меню и тип кухни определены)
  - Каталог svoe-rodnoe.ru доступен

Основной поток:
  1. Система запрашивает список продуктов из каталога svoe-rodnoe.ru с фильтром: сезон = текущий
  2. Система фильтрует продукты по совместимости с типом кухни (матрица совместимости)
  3. Система ранжирует продукты: сначала «в сезоне», затем «скоро появятся»
  4. Система генерирует для каждого продукта объяснение совместимости с кухней через AI
  5. Система определяет, какие блюда из меню можно обновить данным продуктом
  6. Шеф видит карточки продуктов с объяснениями и ссылками на блюда
  7. Шеф нажимает «Перейти к фермеру» — открывается карточка на svoe-rodnoe.ru

Постусловия:
  - Шеф получил список релевантных продуктов с объяснениями
  - Зафиксирован переход на svoe-rodnoe.ru (аналитика)

Альтернативные потоки:
  A1. Шеф хочет отфильтровать только «премиальные» продукты:
    A1.1. Шеф включает фильтр «Премиум»
    A1.2. Список обновляется — показаны только премиальные ингредиенты
  A2. Шеф хочет сортировку по категории:
    A2.1. Шеф выбирает категорию в фильтре (например, «Ягоды»)
    A2.2. Список фильтруется по выбранной категории

Исключительные потоки:
  E1. API svoe-rodnoe.ru недоступен:
    E1.1. Система использует кэшированные данные (TTL 24ч)
    E1.2. Показывается уведомление: «Данные обновлены X часов назад»
  E2. Подходящих продуктов нет:
    E2.1. Система расширяет поиск до смежных типов кухонь
    E2.2. Шеф уведомлён об этом расширении

Критерии приёмки:
  1. Подборка содержит ≥5 продуктов для любого из 10 основных типов кухонь в сезон
  2. Объяснение совместимости генерируется для каждого продукта (1–3 предложения)
  3. Редкие/премиальные продукты помечены соответствующим бейджем
  4. Кнопка «Перейти к фермеру» ведёт на корректную карточку svoe-rodnoe.ru
  5. При недоступности API показываются кэшированные данные не старше 24 часов
```

### Use Case: UC-RECO-002 — Просмотр рекомендаций по обновлению меню

```
ID: UC-RECO-002
Наименование: Рекомендации по обновлению конкретных позиций меню
Акторы: Шеф-повар, Система
Предусловия:
  - Меню загружено (UC-MENU-001)
  - Подборка продуктов сформирована (UC-RECO-001)

Основной поток:
  1. Шеф выбирает продукт из подборки
  2. Система показывает детальную карточку продукта
  3. В карточке: раздел «Подходит для блюд» — список позиций из меню шефа
  4. Для каждого блюда — краткое объяснение: как можно использовать продукт
  5. Шеф может нажать «Добавить в список закупок» (v2.0) или перейти к фермеру

Постусловия:
  - Шеф получил конкретные идеи по применению продукта в меню

Альтернативные потоки:
  A1. В меню нет подходящих блюд для продукта:
    A1.1. Система предлагает идеи новых блюд под концепцию кухни

Исключительные потоки:
  E1. AI не смог сгенерировать объяснение:
    E1.1. Показывается шаблонное описание из справочника

Критерии приёмки:
  1. Для каждого продукта предложено ≥1 блюдо из меню или ≥1 идея нового блюда
  2. Объяснение применения написано на русском языке, понятном для шефа
  3. Время генерации рекомендаций для одного продукта ≤3 секунд
```

## FR-CATALOG: Интеграция с каталогом svoe-rodnoe.ru

**FR-CATALOG-01.** Система должна получать данные о продуктах из каталога svoe-rodnoe.ru (через API или веб-скрапинг).

**FR-CATALOG-02.** Данные каталога должны кэшироваться с TTL 24 часа.

**FR-CATALOG-03.** Система должна поддерживать фильтрацию каталога по: категории продукта, региону фермера, сезонному статусу.

**FR-CATALOG-04.** При переходе на карточку фермера — открывается страница svoe-rodnoe.ru в новой вкладке.

## FR-AUTH: Авторизация и профиль

**FR-AUTH-01.** Дашборд доступен только авторизованным пользователям svoe-shef.ru.

**FR-AUTH-02.** Профиль ресторана сохраняет: тип кухни, последнее меню, историю просмотров.

**FR-AUTH-03.** Один аккаунт может управлять несколькими ресторанами (v2.0).
