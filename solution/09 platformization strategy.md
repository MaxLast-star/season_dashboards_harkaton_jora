## 1. Что заменяется готовыми платформами

| Модуль | Готовое решение | Обоснование выбора |
|---|---|---|
| **Авторизация и SSO** | Существующая auth svoe-shef.ru / Keycloak | Не нужно строить аутентификацию с нуля; интеграция через OAuth2/OIDC |
| **AI-генерация объяснений** | OpenAI GPT-4o-mini / YandexGPT / GigaChat | Собственная LLM нереалистична; API-доступ к лучшим моделям за $0.15/1M токенов |
| **Парсинг PDF-меню** | pdfplumber (Python) / pdf-parse (Node.js) | Open-source библиотеки решают задачу без разработки своего парсера |
| **Кэш** | Redis (upstash.io managed) | Managed Redis без операционной нагрузки; бесплатный тир до 10K команд/день |
| **База данных** | PostgreSQL (Supabase / Railway / Neon) | Managed PostgreSQL с щедрым бесплатным тиром; без DevOps |
| **Деплой** | Vercel / Railway / Render | Хакатон: деплой за 5 минут; автоматические превью-ветки |
| **Аналитика событий** | PostHog (cloud) / Mixpanel | Готовые воронки, retention, dashboards без собственного BI |
| **Мониторинг** | Sentry (ошибки) + Uptime Robot (доступность) | Бесплатные тиры покрывают MVP-нагрузку |
| **Уведомления (v2.0)** | SendGrid / Unisender (email) + ntfy.sh (push) | API-интеграция дешевле собственной почтовой инфраструктуры |

## 2. Что нельзя заменить готовым решением (уникальные модули)

| Уникальный модуль | Почему это конкурентное преимущество |
|---|---|
| **Алгоритм подбора продуктов под кухню** | Матрица совместимости «продукт × тип кухни» — экспертная база знаний, специфичная для российского ресторанного рынка. Готовых решений нет. |
| **Интеграция с каталогом svoe-rodnoe.ru** | Уникальный доступ к базе 10K российских фермеров — эксклюзивное конкурентное преимущество РСХБ, недоступное конкурентам |
| **Контекстуализация рекомендаций под конкретное меню** | Связка «блюдо шефа → сезонный продукт → объяснение» — это не просто LLM, это бизнес-логика поверх LLM с промптами, специфичными для ресторанной отрасли |
| **Визуальный тайм-лайн сезонности** | UX-решение, заточенное под паттерн работы шефа (думает сезонами, а не категориями) |

## 3. Рыночные SaaS-решения и схемы интеграции

### OpenAI API (AI-генерация объяснений)

**Схема интеграции:**
1. Backend получает запрос: `{product_id, product_name, cuisine_type, dish_name}`
2. Формируется промпт: `"Объясни в 2-3 предложениях, почему {product_name} подходит для {cuisine_type} кухни и как его можно использовать в блюде {dish_name}"`
3. POST-запрос к `api.openai.com/v1/chat/completions`, модель `gpt-4o-mini`
4. Ответ кэшируется в Redis (TTL 1ч)
5. Текст объяснения возвращается клиенту

| Плюсы | Минусы |
|---|---|
| Высокое качество русскоязычного текста | Зависимость от иностранного провайдера (риск санкций) |
| Быстрый отклик (1–2 сек) | Стоимость при масштабировании |
| Простой API, документация | Данные передаются за рубеж |

> **Альтернатива для production:** GigaChat (Сбер) или YandexGPT — российские провайдеры, данные остаются в РФ. Переключение через абстракцию LLM-провайдера (стратегия паттерн).

---

### Supabase (PostgreSQL + Auth)

**Схема интеграции:**
1. Supabase предоставляет managed PostgreSQL
2. Прямое подключение через connection string
3. Опционально: Supabase Auth как замена собственного SSO (если svoe-shef.ru не предоставит OAuth)

| Плюсы | Минусы |
|---|---|
| Бесплатный тир: 500MB, 2GB transfer | Vendor lock-in при глубокой интеграции |
| Готовые dashboards и SQL-браузер | Ограничения бесплатного тира при росте |
| Row Level Security из коробки | |

---

### Upstash Redis (кэш)

**Схема интеграции:**
1. Upstash предоставляет Redis через HTTP API (serverless-friendly)
2. Подключение через `UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN`
3. Используется для кэша продуктов (TTL 24ч) и рекомендаций (TTL 1ч)

| Плюсы | Минусы |
|---|---|
| Бесплатный тир: 10K команд/день | Ограничения бесплатного тира |
| Serverless — нет постоянного подключения | HTTP overhead vs TCP Redis |
| Нет DevOps | |

## 5. Стратегия масштабирования

### Техническое масштабирование

```
MVP (хакатон):
  └── Monolith API (Node.js/Python)
  └── Supabase PostgreSQL
  └── Upstash Redis
  └── Vercel/Railway деплой

v2.0 (production-ready):
  └── Разделение на сервисы:
      ├── API Gateway
      ├── Core API (бизнес-логика)
      ├── AI Service (LLM-запросы)
      └── Sync Worker (каталог svoe-rodnoe.ru)
  └── Managed PostgreSQL (RDS / Yandex Cloud)
  └── Redis Cluster
  └── CDN для статики

v3.0 (масштаб):
  └── Горизонтальное масштабирование Core API
  └── ClickHouse для аналитики
  └── Kafka для event streaming
  └── Мобильное приложение (React Native)
```

### Продуктовое масштабирование (модульность)

Дашборд строится как **встраиваемый виджет** (iframe/Web Component), который можно:
- Добавить в личный кабинет svoe-shef.ru (текущий план)
- Встроить в POS-системы и кассовое ПО (iiko, r_keeper) через SDK
- Предоставить как white-label решение для других ресторанных платформ

## 7. Бизнес-модель

**Тип:** B2B2C — РСХБ → Рестораны (покупатели) → Шефы (пользователи)

| Параметр | Значение |
|---|---|
| **Покупатель** | Владелец / управляющий ресторана (принимает решение об оплате) |
| **Пользователь** | Шеф-повар (использует продукт ежедневно) |
| **Ценностное предложение покупателю** | Снижение времени на планирование меню, рост маржи от сезонных позиций |
| **Ценностное предложение пользователю** | Удобный инструмент под рукой; AI-помощник в профессии |

### Каналы выхода на рынок

| Канал | Описание | Приоритет |
|---|---|---|
| **Органический (svoe-shef.ru)** | Встраивание в существующий ЛК для 50K шефов — нулевая стоимость привлечения | 🔴 Главный |

### Стратегическая ценность для РСХБ

Сервис создаёт **экосистемный эффект**:
- Шеф использует дашборд → переходит на svoe-rodnoe.ru → совершает закупку у фермера → фермер получает выручку → РСХБ кредитует фермера → замкнутый цикл
- Данные о спросе ресторанов → аналитика для РСХБ → кредитные продукты под сезонные закупки
