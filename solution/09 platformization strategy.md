# 09. Технологический стек и бизнес-ценность решения

## 1. Использование готовых решений vs. собственная разработка

### Что берём готовым (не пишем с нуля)

| Компонент | Выбранное решение | Обоснование |
|---|---|---|
| **Авторизация** | SSO svoe-shef.ru / OAuth 2.0 | Платформа уже имеет авторизацию; дублирование создаёт риски безопасности и путаницу для пользователя |
| **LLM для объяснений** | GigaChat API / YandexGPT | Российские провайдеры: данные остаются в РФ, нет рисков санкций. GigaChat от Сбера — партнёр РСХБ в госсекторе |
| **Парсинг PDF** | pdfplumber (Python) / pdf-parse (Node.js) | Зрелые open-source библиотеки; нет смысла тратить время хакатона на собственный парсер |
| **База данных** | PostgreSQL (Supabase или Neon на хакатоне) | Реляционная модель необходима для транзакционности; managed-сервис снимает DevOps |
| **Кэш** | Redis (Upstash) | Стандартное решение для кэша; бесплатный тир Upstash достаточен для прототипа |
| **Аналитика** | PostHog (cloud, бесплатный тир) | Воронки, retention, события — без разработки собственного BI |
| **Деплой прототипа** | Railway / Render | Деплой за 5 минут; без настройки серверов |

### Что разрабатываем сами (уникальная ценность)

| Модуль | Почему нельзя заменить готовым |
|---|---|
| **Матрица совместимости продукт x кухня** | Экспертная база знаний для российского рынка; готовых аналогов нет |
| **Алгоритм ранжирования и подбора** | Бизнес-логика поверх данных каталога svoe-rodnoe.ru: сезон + кухня + редкость |
| **Интеграция с svoe-rodnoe.ru** | Эксклюзивный источник данных о 10 000 российских фермеров; недоступен конкурентам |
| **Промпты и контекстуализация AI** | Шаблоны объяснений, заточенные под ресторанный домен и конкретное меню шефа |
| **Визуальный тайм-лайн** | UX под специфику работы шефа (мыслит сезонами и категориями блюд) |

## 2. Бизнес-ценность решения в измеримых показателях

### 2.1 Ценность для шеф-повара

| Проблема до | Решение | Измеримый результат |
|---|---|---|
| Поиск сезонных продуктов занимает 1-3 часа (Telegram, Авито, личные звонки) | Дашборд подбирает релевантные продукты за секунды | Сокращение времени поиска с ~2 часов до 15 минут (цель BG-01) |
| Нет понимания "окна сезонности" — когда заказать заранее | Тайм-лайн показывает текущий + следующие 2 месяца | Шеф может планировать меню на 8 недель вперёд, а не реагировать постфактум |
| Продукты ищутся без учёта типа кухни — много нерелевантных вариантов | Фильтрация по типу кухни + AI-объяснение совместимости | Снижение "информационного шума": из 100 продуктов шеф видит только релевантные для своей кухни |
| Нет объяснения "зачем этот продукт именно мне" | AI генерирует 2-3 предложения с обоснованием под кухню ресторана | Конверсия "просмотр -> переход к фермеру" цель >= 25% (KPI BG-04) |

### 2.2 Ценность для ресторана (бизнес-метрики)

| Метрика | До внедрения | Цель после внедрения | Как считаем |
|---|---|---|---|
| Время обновления сезонного меню | 3-7 дней (ручной поиск + переговоры) | 1 день (подборка готова за 15 мин, переход к фермеру — 1 клик) | Опрос шефов через 3 мес. после запуска |
| Доля сезонных позиций в меню | 10-20% (по данным отрасли) | 30-40% через 6 мес. использования платформы | Анализ загружаемых меню шефов |
| Маржинальность сезонных блюд | Базовая (нет оптимизации закупок) | +5-10% к марже за счёт прямых закупок у фермеров (без посредников) | Опрос рестораторов через 6 мес. |
| Среднее количество поставщиков | 2-3 постоянных поставщика | 5-7 (добавляются фермерские хозяйства из каталога) | Данные из svoe-rodnoe.ru |

### 2.3 Ценность для платформы РСХБ (экосистемные метрики)

| Метрика | Цель | Горизонт | Источник данных |
|---|---|---|---|
| MAU шефов на svoe-shef.ru | +5 000 активных пользователей модуля | 6 мес. после запуска | PostHog / аналитика платформы |
| Переходы на svoe-rodnoe.ru из дашборда | 25% просмотров -> переход к фермеру | 3 мес. | CTR кнопки "К фермеру" |
| Рост B2B-транзакций на svoe-rodnoe.ru от ресторанов | +30% заказов с тегом "ресторан" | 6 мес. | CRM svoe-rodnoe.ru |
| Retention шефов на svoe-shef.ru | Пользователи модуля удерживаются на 40% лучше, чем без него | 3 мес. | Retention-когорты в PostHog |
| NPS шефов по функции | >= 50 | 3 мес. | In-app опрос после первого использования |

### 2.4 Механизм создания ценности (value flywheel)

```
Шеф находит продукт через дашборд
        |
        v
Переходит на svoe-rodnoe.ru -> совершает покупку у фермера
        |
        v
Фермер получает выручку -> обновляет каталог -> добавляет сезонные продукты
        |
        v
Каталог становится богаче -> дашборд даёт лучшие рекомендации
        |
        v
Больше шефов используют дашборд -> больше трафика на svoe-rodnoe.ru
        |
        v
РСХБ видит рост транзакций -> кредитует фермеров под сезонные закупки
        |
        (цикл повторяется)
```

## 3. Технологический стек (итог)

| Слой | Технология | Обоснование |
|---|---|---|
| **Frontend** | React + TypeScript | Компонентный подход для переиспользования карточек и фильтров |
| **Backend** | Node.js (Express) или Python (FastAPI) | Зависит от стека команды; оба поддерживают async/await для AI-запросов |
| **База данных** | PostgreSQL | Транзакционность, JSON(B), зрелость |
| **Кэш** | Redis | TTL для каталога (24ч) и AI-ответов (1ч) |
| **LLM** | GigaChat API / YandexGPT | Российские провайдеры, данные в РФ |
| **Парсинг PDF** | pdfplumber (Python) | Надёжный open-source парсер |
| **Аналитика** | PostHog | Voronki, retention, события — без собственного BI |
| **Деплой** | Railway / Render | Быстрый деплой без DevOps для прототипа |
| **Мониторинг ошибок** | Sentry | Бесплатный тир, интеграция за 5 минут |
